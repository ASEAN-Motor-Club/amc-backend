# Known-mod parts — second detection layer for /check_parts

**Date:** 2026-09-06 · **Requester:** Yuuka · **Trigger:** Yuuka's `/check_parts` on
prod flagged 7 parts `[unknown]` on her Elisa2 — all from the client-side
**More Tuning** mod (Nexus mods/18).

## Reproduced live (prod, guid 3F40FA9F…, 48 parts / 1312 stock keys)

| Slot | Key | MT catalogue match |
|---|---|---|
| 2 | `20tfsi` | engine (90 petrol/diesel engines) |
| 3 | `gm6T70` | transmission (94 new transmissions) |
| 5 | `SuperchargerStage3` | supercharger (4 added, stage 3) |
| 19–22 | `RallyTire` ×4 | tires (16 new tires, "Rally & Cross") |

Key naming is **prefix-irregular** → the registry matches exact keys
(case-insensitive), optional prefixes per mod entry.

## Design (per Yuuka)

- Do **not** fold mod parts into the stock catalogue (gamedata.db stays pure).
- Separate **list file** consulted as a **second layer** — only when the stock
  detection returns unknown: `src/amc/data/known_mod_parts.json`.
- Matched parts render `[More Tuning]` (label from file) instead of
  `[unknown]`; summary counts split per mod label.
- `[MODS]` tag semantics unchanged: matched parts remain a subset of
  `detect_custom_parts` output, so `has_custom_parts` still sees them.

## Data source for the full catalogue

More Tuning is Nexus-only (no workshop pak; not hosted on any AMC server).
Pak needed from Yuuka to extract the complete key list via mt-pak-extract.
Until then the registry ships with the 4 live-confirmed keys above.

## Changes

1. `src/amc/data/known_mod_parts.json` — registry: `{mod_id: {label, source,
   updated, keys[], prefixes[]}}`, seeded with the 4 confirmed keys.
2. `src/amc/mod_detection.py` — `load_known_mod_parts()` (cached loader,
   degrades to `{}` + warning on missing/invalid file) +
   `match_known_mod_parts(custom_parts)` → `[(part, label), ...]`.
3. `src/amc/commands/vehicles.py` — `/check_parts` popup: second layer after
   `detect_custom_parts`, per-mod markers + split summary.
4. Tests: loader (seed integrity), matcher (case-insensitivity, non-match),
   popup rendering (mixed known-mod/unknown/stock).

Scope note: only `/check_parts` gets the label layer now; `/check_mods`,
cargo gate, and the background tag task keep stock-only detection (same
behavior as today for MT parts). Extending later is additive.
